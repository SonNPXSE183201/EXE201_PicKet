## Quy tắc cập nhật

- `implemented` nghĩa là code đã tồn tại nhưng chưa đủ bằng chứng release.
- `verified` yêu cầu automated test và kiểm thử trên môi trường staging/device.
- Chỉ các capability P0 ở trạng thái `verified` mới cho phép bắt đầu cutover.
- Flutter chỉ được archive sau staged rollout Expo và rollback window.

Parser nhận ngày `dd/mm`, `dd-mm`, `dd.mm` với năm 2/4 chữ số; tổng tiền tiếng Việt/Anh, giá có hậu tố thập phân và item dạng số lượng được kiểm tra, còn metadata/tạm tính/tiền khách/tiền thừa bị loại. - OCR fallback có private job schema, idempotency và quota 24 giờ theo gói (`free 3`, `plus 30`, `pro 100`); Dart worker và PP-OCRv5 mobile CPU provider đang chạy trong private Docker network trên VPS production. Còn cần E2E qua một ảnh hóa đơn thật đã ẩn danh bằng session test để nâng lên `verified`.
- Supabase remote đã áp dụng migration `202610080005` và `202610080006`; database lint không còn warning/error, PostgREST từ chối anon trên OCR job/RPC đúng mã `42501`.

- Dart worker có lease 5 phút, tối đa 3 lần thử, adapter multipart PP-OCR, validate output, complete/fail và cleanup Storage có acknowledgement. Multipart giữ đúng MIME `image/jpeg`, `image/png` hoặc `image/webp`; 57 Dart test pass.
- Migration worker `202610090001` đã đồng bộ local/remote và database lint không có lỗi. Worker production compile thành `apps/api/build/bin/ocr_worker.exe`.
- Migration receipt `202610090002` đã đồng bộ local/remote: structured receipt, tối đa 100 line items, exact-hash unique và fuzzy duplicate RPC; Dart API production build nhận đủ 3 route receipt.

- Next.js có `/receipts` và `/receipts/[id]`: liệt kê receipt, tạo signed URL ảnh private 5 phút và sửa metadata/tối đa 100 line items bằng Server Action đã xác thực. Mọi update gửi `expectedVersion`; production build có 23 route và hai route receipt là dynamic server-rendered.
