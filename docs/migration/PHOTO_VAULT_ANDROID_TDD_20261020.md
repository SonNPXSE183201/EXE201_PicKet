## Implementation

- Managed keepsake photos under owner-specific document and cloud-cache directories are now AES-GCM envelopes, bound to `keepsake-photo:<owner>` and the existing SecureStore device key. Rendering decrypts into an in-memory data URI; persisted references remain durable file URIs.
- Uploads and guest backups read original decoded bytes, not ciphertext. Cloud downloads are validated/encrypted from memory without a plaintext download file. Image signatures determine JPEG/PNG/WebP content type.
- Legacy local rows are encrypted with compare-and-swap reference migration. Legacy cloud files remain readable and migrate when refreshed. Originals are not deleted before references commit. This migration path is implemented but the full native legacy/race matrix remains open.
- Cleanup loads SQLite and encrypted cache references, skips on reference discovery failure, protects active save/replay/read/export/restore through owner leases, and blocks new operations during an exclusive sweep. It removes at most 20 files/20 MB per sweep, older than 24 hours, in explicitly owned directories. Deletion/acknowledgement no longer eagerly removes a possibly referenced image.
- Scope is the app-managed keepsake store/cache, not encryption of the user's Android photo library or all system/picker temporary files.

## Backup key derivation

The portable JS PBKDF2 path produced long native waits/timeouts in the expanded test. Android 37.2 also had an independently observed UWB system-service crash loop; a comparison on Android 35 did not justify blaming UWB alone. Earlier harness overlap with Share Sheet was excluded from acceptance.

A local Android Expo module now uses the platform `PBKDF2WithHmacSHA256` provider in an AsyncFunction worker. The envelope, 210,000 rounds, 32-byte key, salt/nonce sizes and AES-GCM format are unchanged. Passwords cross the bridge as UTF-8 bytes without normalization. Native errors do not downgrade silently. Android API 24/25 retain the portable fallback because the SHA256 provider requires API 26; missing native module on Android gives an APK-update message at backup use rather than crashing startup.

This uses the existing Expo module mechanism, not a new crypto package: [Expo local modules](https://docs.expo.dev/modules/get-started/), [AsyncFunction dispatch](https://docs.expo.dev/modules/module-api/#asyncfunction).
